# Internationalisation (Peak C9)

All user-facing strings in the web app live in one message
catalogue: `web/src/i18n/messages.ts`. Components never
hardcode copy; they read the active catalogue:

```tsx
import { fmt, m } from '../i18n/messages';

<h1>{m.library.title}</h1>
<p>{fmt(m.library.countLine, { count: total, word })}</p>
```

- `m` is the active locale's catalogue. Today the only
  locale is English (`en`), so `m === en`.
- `fmt(template, vars)` fills `{name}` placeholders.
  Unknown placeholders are left as-is, which makes a
  missing variable visible instead of silent.
- Strings with markup are split into before/after keys
  around the markup (see `auth.forgotSentBefore` /
  `forgotSentAfter`), so translators translate whole
  fragments, never tags.
- Server-driven text (API error messages, snippet content,
  user data) is NOT in the catalogue - it is data, not UI
  copy.

## Adding a locale

1. Add the locale code to the `Locale` type in
   `messages.ts`.
2. Add a full catalogue for it typed as `Messages`
   (TypeScript enforces that every key exists - the type
   is derived from the English catalogue).
3. Register it in the `catalogues` record and choose it
   in `activeLocale` (today a constant; a user preference
   can replace it without touching components).
4. The catalogue test (`web/src/i18n/messages.test.ts`)
   fails if any locale's key set differs from English or
   any leaf is empty.
5. For a right-to-left locale, set `dir="rtl"` on the
   document root when the locale activates. Layout uses
   logical properties and flex/grid throughout; the
   `__rtl` dev route (RTL test page, `RtlTestPage.tsx`)
   renders representative UI inside `dir="rtl"` with
   sample Arabic text so mirroring can be checked before
   a real translation exists.

## Rules for new strings

- Add the string to the catalogue first, under the
  section for its surface (`library`, `snippet`, ...),
  then reference it. Never inline copy in a component.
- Keep placeholders minimal and named (`{count}`,
  `{name}`); plural forms are separate keys chosen by
  code (`savedOne` / `savedMany`) until a locale needs a
  real pluralisation engine.
- Do not translate brand or CLI text: `ForgeHub`, `fg`,
  command examples and code stay as-is.
