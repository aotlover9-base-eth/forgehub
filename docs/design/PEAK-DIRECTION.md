# Peak design direction - the Material You rebuild

- **Status:** Normative for Peak Phase A (A1-A8). Written in WP A0, 2026-11-22.
- **Law:** `agent.md` section 8 and `docs/design-spec.md` win on any conflict. This document applies them to the post-Observe product and records what the A0 audit found.
- **Supersedes:** the Observe theme direction of 2026-11-20 (dark glass, monochrome, Instrument Serif). The owner is not satisfied with that look; this phase replaces it with faithful Material You 3.

## 1. What the audit found (evidence: `docs/screenshots/peak-audit/`)

Every route was captured at 360, 768 and 1280 px against a seeded server (user `ada`, six snippets, three public, one with two versions): 36 captures in the shipped pinned-dark theme plus two light-forced captures. Objective checks: no route overflows horizontally at any width. The problems are qualitative and structural:

1. **There is no light theme in practice.** `index.html` pins `data-theme="dark"`, and the `.observe-app` scope in `tokens.css` re-points every colour role to monochrome glass values. Forcing `data-theme="light"` at runtime produces a pixel-identical dark screen (compare `library-1280.jpg` and `library-1280-lightforced.jpg`). The complete generated light scheme exists in `tokens.css`/`tokens.ts` and is unreachable.
2. **Glass over a moving smoke backdrop hurts legibility.** Panels are translucent black (surface at 35% black) with a 14 px blur over `observe-bg.jpg`. Where the smoke is bright, card text and code sit on a busy, low-contrast background (Library rows, Editor code area). Code - the product's hero content - is the worst affected.
3. **Colour carries no information.** The Observe scope makes white the only accent: primary, secondary and tertiary all collapse to white or white-alpha. The M3 rule "Public chip is the one tertiary use" is unimplementable; selection, links and the primary action are indistinguishable in kind.
4. **The active navigation state is a white pill** (full-surface inversion), not the M3 secondary-container indicator. On compact the fixed bottom bar overlaps scrolling content: on `home-360.jpg` the "Popular this week" heading and a snippet row are partially hidden behind the bar.
5. **Touch targets under 48 px are common on compact.** Measured native elements: landing nav links 20-24 px tall, "Create account" 36 px, text links 16 px, the Library/Explore search input 22 px, the snippet "Raw" action 40 px, snippet links on Home/Profile 16-19 px.
6. **Serif display type is mixed into a sans product.** The landing headline is Instrument Serif (a deliberate 2026-11-20 exception); the rest of the product is Roboto Flex. ADR 0009 decides this: the serif goes.
7. **Hierarchy is flat inside the app.** List rows in Library are very tall (name, description, then a separate row of tag chips), so a 1280 px viewport shows about five snippets. The Editor's Checks panel is a large mostly-empty glass card. The Snippet page tab bar stretches its two tabs to opposite ends of a full-width bar, which reads as broken.
8. **The top app bar has no search entry and no account menu** - just a username label and two text buttons (Settings, Log out). The design spec (section 2) asked for search entry, theme menu and account menu.
9. **Empty states exist but teach little.** Home's empty state and Library's empty state predate the Home/Library split and do not walk a new user through install-CLI-then-record.
10. **Motion is decorative, not M3.** The landing has a 70 s background drift and staggered entrances; route transitions are a single fade-rise keyframe, not shared-axis. Reduced-motion handling exists on the landing video only.

**Controlled colour rules (unchanged from agent.md section 8):** neutral tonal surfaces; `primary` only for the main action, selection, focus and progress; `tertiary` at most once per screen (the Public visibility chip); `error` only for errors and destructive confirmations; tags always neutral outlined chips; no gradients; no glass blur as decoration; no colour outside tokens (`check-tokens` enforces).

**Theme preference:** `system` (default), `light`, `dark` - stored in localStorage under `forgehub-theme` in try/catch, applied by an inline script in `index.html` before first paint, switchable in Settings and the app bar account menu. The Observe glass scope (`.observe-app`, `--fh-observe-*`) is removed in A1; the landing is rebuilt on the same tokens in A5. There is no third "classic" theme: keeping the glass scope token-driven alongside two real schemes doubles every contrast obligation for a look the owner rejected.

## 4. Shape and elevation

Shape scale (tokens): extra-small 4, small 8, medium 12, large 16, extra-large 28, full 9999. Buttons, chips, FAB, nav indicators: full. Cards: large (16). Dialogs and bottom sheets: extra-large (28) top corners for sheets. Text fields: extra-small top corners (filled) per M3. CodeBlock: medium (12).

Elevation is tonal first: page background `surface`, cards `surface-container-low` (filled) or `surface` + outline (outlined), menus/dialogs `surface-container` with level 2 shadow, FAB `primary-container` with level 3 shadow. Shadows use the existing `--md-sys-elevation-1/2/3` tokens only, and only on menus, dialogs, the FAB and the top app bar on scroll. No blur, no glass.

## 5. Motion

Tokens (verified against M3 easing and duration specs, 2026-11-22):

- Emphasized: `cubic-bezier(0.05, 0.7, 0.1, 1)` (decelerate form used for entrances), emphasized-accelerate `cubic-bezier(0.3, 0, 0.8, 0.15)` for exits.
- Standard: `cubic-bezier(0.2, 0, 0, 1)`; standard-accelerate `cubic-bezier(0.3, 0, 1, 1)`.
- Durations: short1-4 = 50/100/150/200 ms (state changes, selection controls 200 ms standard), medium1-4 = 250/300/350/400 ms (route shared-axis 300 ms emphasized, dialogs, sheets), long1-4 = 450/500/550/600 ms (large expansions only).
- Route transitions: shared-axis (fade + 24 px slide) at medium2 emphasized. List-to-detail: same axis. Copy feedback: icon swap + snackbar. Save feedback: inline check, short4.
- `prefers-reduced-motion`: all of the above collapse to a short fade or instant; the intro video never autoplays; skeletons are static. No looping decorative animation anywhere (the 70 s smoke drift is deleted with the Observe theme).

## 6. Layout and spacing

Spacing tokens (4 pt grid): 4, 8, 12, 16, 24, 32, 48, 64 (`--fh-space-1..8`). Page margins: 16 px compact, 24 px medium and expanded. Content max width 1200 px centred. Window classes (M3): compact < 600, medium 600-839, expanded >= 840 (the existing `widthClassFor` already implements exactly this).

Shell: small top app bar on compact/medium, medium top app bar on expanded; navigation bar on compact (surface-container, secondary-container active indicator, labels always visible), navigation rail on medium, navigation rail with labels beside icons (extended) or a standard drawer on expanded - A3 ships the extended rail to keep one code path with medium. FAB on Library and Profile (compact/medium), extended FAB on expanded. Global search entry sits in the app bar and opens a full search view on compact, a search field that routes to Explore elsewhere.

Density: comfortable default; a compact density option in Settings (A5) reduces list item vertical padding from 12 to 8 px. Both densities keep 48 px minimum touch targets on compact.

## 7. Screen wireframes (text form; A5 implements)

**Landing `/` (logged out).** Top app bar (wordmark, Explore, Log in, filled Create account). Hero: display headline "Save a command once, run it anywhere." in Roboto Flex, one body-large line, a filled card (surface-container-low, shape large) containing the real `fg ubuntu-setup` exchange in a CodeBlock with the confirmation card visible, and two actions (filled Create account, outlined Explore). Then three filled cards in a row on expanded, stacked on compact: Save it on the web / Run it anywhere / Safety first, each icon + title + two lines. Then the intro video section on tokens (poster, controls, captions; no autoplay under reduced motion). Footer: source link, "No tracking", version. No serif, no smoke, no glass.

**Home `/home`.** Headline "Welcome back, <name>". Quick actions row: filled New snippet, tonal "Run from CLI" card with a copyable `fg` command. Recent snippets as an M3 list (two-line items, visibility chip trailing). Recent activity list (version events). Empty state: two numbered steps (install the CLI, record your first command) with copyable commands and one filled action.

**Library `/dashboard`.** Headline + count. Search field (filled, leading icon). Filter chips row (All / Private / Unlisted / Public) + sort menu + density toggle. Snippets as M3 list items (leading terminal icon, name title-medium, description + version + updated body-small, trailing visibility chip and overflow menu). Bulk-select mode replaces the app bar (count, Delete, Visibility, Add tag, Close). Keyboard: j/k moves, slash focuses search, n new. On expanded, selecting an item opens a detail side sheet (360 px) with the code and Run card instead of navigating away. FAB / extended FAB.

**Editor `/new`, `/:owner/:name/edit`.** Expanded: two panes - form + editor left (min 0), Checks panel right (surface-container-low card): validation errors with line numbers (error role, icon + text), detected variables as input chips, secret findings blocking with error styling, lint warnings labelled "Warning" in text with the warning icon (never colour alone). Compact/medium: single column, Checks below the editor. Ctrl+S saves; unsaved-changes guard dialog; version conflict opens a dialog (Reload theirs / Save as new version / Keep editing). Visibility as segmented buttons. Tags as input chips.

**Snippet `/:owner/:name`.** Header: avatar initial, owner/name headline, description, chips row (visibility = the one tertiary Public chip or neutral, version, updated). Run card (filled, prominent): `fg <name>` or `fg owner/name` in Roboto Mono with copy icon button and the safety line. Tabs: Code - Versions - Forks (primary tabs, left-aligned, content-width). Code tab: CodeBlock on surface-container-highest with line numbers and copy. Versions: list with two-select checkboxes and a Compare button opening the diff (DiffView: +/- gutter + tonal shift). Forks: list of forks with owners. Hostile content renders as inert text (tested).

**Explore `/explore`.** Search bar at top (routes query), facet chips (tag suggestions from popular tags), sort segmented control (Relevance / Most stars / Recent). Result cards (filled): name, owner, description, tags, stars/forks counts. Load more button with stable cursor. No-results state echoes the query as text with one Clear action.

**Profile `/:username`.** Avatar initial in a primary-container circle, username headline, bio, joined date. Public snippets list (same item as Library, read-only). No private counts, ever.

**Settings.** Expanded: vertical tabs left (Appearance, Profile, Security, Tokens, CLI, Danger zone), content right. Compact: stacked sections with headline-small heads. Appearance: theme radio group (System / Light / Dark), density switch. Tokens: list + Create; the one-time reveal shows the token in a CodeBlock with copy and an "I've copied it" checkbox gating Done. Danger zone: error-outlined card, delete account requires typing the username into a field.

**Device `/device`.** One centred card (max 480 px): client name headline, body text stating exactly what approval grants, the user code in Roboto Mono, Deny (outlined) before Approve (filled) in tab order. Success and denied end states replace the card content. Never auto-approves.

**Auth pages.** Centred card (max 480 px) on surface: headline, filled fields with inline error text and supporting text, password visibility toggle icon button, generic failure banner (error-container), rate-limit message with the wait time. Primary action full-width filled button.

**404 / error boundary.** Centred: headline-small message, one filled "Go home" action. The error boundary adds a short reference id (body-small, selectable) and never a stack trace.

## 8. Guidance relied on (Material 3, read 2026-11-22)

- Color system overview (m3.material.io/styles/color/system/overview): roles are algorithmically paired for contrast; tone-based surface container roles replace elevation-tinted surfaces; fixed roles stay constant across themes.
- Typography overview (m3.material.io/styles/typography/overview): five roles (display, headline, title, body, label), 15 baseline styles, tokens carry size/line-height/weight/tracking; Roboto Flex is the variable UI face.
- Window size classes (m3.material.io/foundations/layout/applying-layout/window-size-classes): compact < 600, medium 600-839, expanded 840-1199; navigation swaps bar -> rail -> drawer across classes; two panes recommended on expanded; ideal text line length 40-60 characters.
- Motion tokens (m3.material.io/styles/motion/easing-and-duration/tokens-specs): emphasized decelerate cubic-bezier(0.05, 0.7, 0.1, 1), emphasized accelerate cubic-bezier(0.3, 0, 0.8, 0.15), standard cubic-bezier(0.2, 0, 0, 1); durations short 50-200, medium 250-400, long 450-600; selection controls 200 ms standard.
- Navigation bar specs (m3.material.io/components/navigation-bar/specs): container surface-container, active indicator secondary-container with on-secondary-container icon, state layers hover 8% / focus 10% / pressed 10%.
- Component specs for cards, chips, dialogs, menus, search, FAB, lists and snackbars follow the same site and the existing design-spec section 5 inventory; A4 verifies each rebuilt component against its spec page and notes deviations in its report.
