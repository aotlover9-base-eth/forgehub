# Step 18 Report - CLI TUI, offline mode, completions, polish

## 1. Summary

The CLI gained its interactive face and its finishing polish: a full-screen TUI (`forgehub ui`, ratatui + crossterm) whose run path is the *same* `cmd_run` the shell command uses, an explicit offline mode (global `--offline` + `run --offline` from the cache), a size-capped LRU run cache with `cache list|clear`, an `update --check` that reports but never self-replaces, `--verbose` request logging with tokens never printed, examples in every subcommand's help, and generated man pages for the whole command tree. Release re-measure: `--version` mean 5.09 ms, local dry-run mean 8.00 ms, binary 9.2 MiB - all inside budget.

## 2. What was built

- **`crates/forge-cli/src/tui.rs`** - tabs Local · Mine · Explore; fuzzy filter (`/`, subsequence scoring with consecutive/word-start bonuses); detail pane with the same numbered command view as the confirmation card; keys j/k/arrows, Tab/←/→, Enter/r run, d dry-run, p push, l pull, f fork, s star, e edit, ? help, q quit; Ctrl-C quits from anywhere. State logic (`TuiState::handle`) is separated from rendering and unit-tested; rendering is split into header/main/detail helpers. Terminal is restored on quit, on error and on panic (hook); non-TTY stdout refuses with a what/why/fix message; below 60×20 a "Terminal too small" note renders instead. Colour policy: one accent + dim + error/warn only; `NO_COLOR` or `TERM=dumb` → all plain + borderless (ASCII fallback). Cloud tabs load lazily on first visit; errors render in-pane, never crash the UI.
- **Same safety path, by construction**: the TUI returns an `Action`; `main::dispatch_ui` executes it through the ordinary commands - Run/DryRun via `cmds::cmd_run` (identical trust confirmations, typed `yes`, hash-change diffs), Push/Pull/Fork via `sync::cmd_push/cmd_pull/cmd_fork`, Star via the new `sync::cmd_star`, Edit via `cmds::cmd_edit` (cloud items must be pulled first, with that exact instruction in the error).
- **`crates/forge-cli/src/cache.rs`** - cache entries parsed from `<owner>--<name>--v<N>.yaml`; `evict_lru` deletes oldest bodies first and prunes pointers whose body vanished; `cache_put` (Step 13) now enforces the cap after every write (config `cache_max_mb`, default 100, matching spec-cli §5); `cache list` (human + `--json`) and `cache clear` (human + `--json`).
- **`crates/forge-cli/src/update.rs`** - `update --check`: registry `/version` first, then the GitHub latest-release API (`FORGEHUB_GITHUB_API` overrides the API base for mirrors/tests); numeric per-segment version comparison; prints the release URL and the reinstall hint; **never downloads or replaces anything** (pinned in spec-cli §5). Failure is a what/why/fix error naming the releases page.
- **Globals**: `--offline` (cloud commands fail fast in `sync::session` with an offline what/fix message; local commands and `run --offline` unaffected) and `-v/--verbose` (one stderr line per request: registry base, status, duration - tokens never logged). Progress output remains TTY-only, as before.
- **Help & docs**: `after_help` Examples (with `fg …` lines) on all 34 subcommands, enforced by a snapshot test; man pages generated by the binary itself (`forgehub --gen-man docs/man`, clap_mangen) - 45 pages in `docs/man/`, including per-subcommand pages with their Examples sections. spec-cli.md §3 now documents the JSON key sets for `status`, `cache list|clear`, `trust list` and `update --check` (verified against the implementations; the `status` entry was corrected to the keys the code actually emits).

## 5. Deviations and problems

- **No PTY end-to-end TUI test.** This environment has no PTY harness, so the TUI's interactive loop itself (keystrokes in a real terminal) is not driven end-to-end. What is proven: the full state machine by unit tests, the non-TTY refusal by integration test, and - by construction - that every TUI action dispatches to the same command functions the CLI tests already exercise (including the trust path). A PTY-driven pass remains a Step 20 candidate.
- **Man pages not render-checked**: `man`/`groff` are not installed here, so the roff was not rendered; the pages are standard clap_mangen output and their text content (incl. Examples) was verified by grep.
- **`forgehub update` without `--check`** performs the check anyway - checking is the only behaviour the command has (help text says so: "there is no self-update mode").
- `update --check`'s GitHub path cannot see the private repo unauthenticated, so until the repo is public or a registry is configured it will report "could not check" - honest behaviour, recorded here rather than hidden.
